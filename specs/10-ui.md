This spec covers what those views share: the app shell, the Editor infrastructure, the designer-chat-panel pattern, and cross-cutting conventions.

## 2. App shell

- **Stack:** React 19 + TypeScript, Vite, TanStack Router + Query, Tailwind. Flow visualization: React Flow. Code/text editing: CodeMirror 6.
- **Navigation:** left rail with the seven areas + a Breadboard dashboard (health metrics: need-input rate trend, spend vs. rate limit, gated/suspended session counts, recent eval regressions).
- **Global search** (`⌘K`): unified across content nodes (FTS over title/aliases/body, [01](01-data-model.md) §3.1) and config definitions (slug/title), results grouped by type.
- **Review affordance:** persistent badge showing the current user's review-queue count (open need-input requests targeted at them + gated sessions awaiting their verdict); links into the Review queue filter ([09](09-content.md) §5.1). Gate items surface the per-artifact **approve / request-changes** verdict actions ([02](02-sessions-orchestrator.md) §5.4).
- **Deep links:** every node, session, step, and config definition has a stable URL (`/n/<uid>`, `/s/<session_id>`, `/config/<uid>`, …) — config URLs use the definition's permanent UID ([01](01-data-model.md) §6.2) so links survive renames; the UI displays the slug. `[[UID|title]]` links rendered anywhere in the UI resolve to `/n/<uid>`.

## 3. Shared Editor infrastructure

One editor foundation backs every content-editing surface (Knowledge Notes, Task bodies, editable Artifacts):

- **CRDT collaboration:** CodeMirror 6 bound to the node's Y.Doc via the WebSocket provider ([07](07-knowledge.md) §6); presence/awareness cursors; offline-tolerant (Yjs buffering) with reconnect. The binding is **custom**: one concatenated Markdown view over the Y.Array-of-blocks body, mapping edits to per-block Y.Texts ([07](07-knowledge.md) §12) — this is what makes the attribution layer and block-anchored comments below possible.
- **Markdown-native:** source editing with live preview toggle; no rich-text schema.
- **Properties panel:** the frontmatter `Y.Map` rendered as a form (title, tags, domains, type-specific fields).
- **Attribution layer:** per-block authorship display; AI-edited blocks highlightable; one-click revert of an AI write to its `pre-ai-edit` revision ([07](07-knowledge.md) §5.3).
- **Revision browser:** list of named revisions with trigger labels + author; diff any two; restore (as a new forward revision, never history rewrite).
- **Comments rail:** anchored comments with staleness handling ([09](09-content.md) §4); select-text-to-comment.
- **Wiki-linking:** `[[` triggers autocomplete over node titles (grant-filtered); inserts `[[UID|title]]`; hover previews; backlinks panel.
- **Read-only mode** for connector-sourced Notes and non-editable states, with the reason displayed.

## 4. Designer-chat-panel pattern

The circuit, tool, and subagent editors all include an **always-visible side chat panel** — conversations with designer Subagents equipped with the config-editing tools ([06](06-toolbox.md) §3). Shared behavior:

1. The panel runs a Session (`kind: intake-conversation` mechanics, different shipped Subagent per editor: `circuit-designer`, `tool-designer`, `subagent-designer` — all team-customizable).
2. The designer Subagent has read access to the open definition (and its references) plus `propose_config_change`.
3. **Propose-review-commit:** AI writes changes to a branch; the editor renders the diff *in the editor's native form* (flow-graph diff for circuits, code diff for tools, config-form diff for subagents) plus raw text; the user requests revisions in-chat, then commits (merge) or discards.
4. For circuits with evals: the review state offers "run evals against this branch" ([04](04-evals.md) §7).
5. Manual edits and chat proposals coexist: manual edits are working-tree changes the user commits directly; the panel sees the working tree, so conversation is always about what's on screen.

This pattern is the UI half of "AI can propose edits to any component, with human gating" ([00 — Overview](00-overview.md) §1.2).

## 5. Cross-cutting conventions

- **Lineage affordances everywhere:** any node chip shows type + title; context menu offers "open", "view lineage", "view producing session". Jumping from an Artifact to the Session chat history that spawned it is always ≤2 clicks ([01](01-data-model.md) §4.4).
- **Cost visibility:** Sessions and steps display cost inline; the dashboard shows spend against the rate limit.
- **Gated/blocked prominence:** suspended-gate Sessions are flagged in Sessions history, the dashboard, and the review queue.
- **Optimistic UI only on CRDT surfaces;** config-plane mutations wait for commit confirmation.
- **Keyboard-first:** `⌘K` search, `g` + letter area jumps, `e` to open editor from any viewer.

## 6. v1 cutline

**In:** app shell + dashboard; all fourteen views listed in §1; shared editor with all §3 features; designer chat in the three config editors; global search; deep links.

**Out (future):** mobile layout; theming; notification center (v1 is pull-based); multi-Breadboard switcher (pairs with federation); accessibility audit beyond baseline semantics (tracked, not gating v1).
